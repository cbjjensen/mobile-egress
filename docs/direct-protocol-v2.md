# Direct protocol v2 implementation contract

This is the shared implementation contract for the 2026-10-03 direct Client/phone migration. It is not evidence of completed implementation or physical acceptance. No legacy relay endpoint is a fallback.

## Encoding and trust

QR/export bundles are unpadded base64url of UTF-8 JSON. Decoders reject unknown fields, duplicate keys where supported, trailing values, invalid UTF-8, excessive size (64 KiB decoded), and incompatible versions/types. HTTPS origins have no userinfo/query/fragment/path except optional `/`. The Client normalizes DNS case, IP spelling, numeric ports and omitted/default HTTPS port 443, and removes trailing `/`. Endpoint acknowledgements accept those equivalent authorities, including configurations stored before normalization; a different host or numeric port still rejects. TLS 1.3, private per-Client CA pin, hostname/IP SAN validation, Agent P-256 non-exportable key and ClientAuth certificate. Each direct Client uses a new authority/server certificate, not old relay trust. Administrators only use existing authenticated local OS IPC.

Invitation JSON: `version:2`, `type:"mobile-egress-direct-invitation"`, `clientId` (stable UUID), `displayName`, `endpoint` (HTTPS origin), `caCertificatePem`, `invitationId` (UUID), `capability` (32 random bytes, unpadded base64url), `expiresAt` (RFC3339 UTC), `role:"agent"`. One active invitation, ten-minute first-redemption window; same-CSR retry is idempotent. First redemption binds the invitation to a pairingId (UUID) and CSR public key. Cancellation prevents further use; replacing a paired phone requires explicit revocation. Retain committed issued credentials to recover acknowledgement/delivery loss, without allowing a different CSR/key to redeem them.

## Public APIs

- `POST /v2/direct/enroll`: pinned server TLS, no client certificate required, JSON `{clientId,invitationId,code,role:"agent",csrPem}`. First/repeated same-key issuance returns HTTP 201 and `{certificatePem,caCertificatePem,serial,role:"agent",clientId,pairingId,generation}`. Certificate chain includes CA; serial uppercase hexadecimal. Phone persists key/pending request before first send and issued identity before ACK. No redirects. Reject old relay enrollment.
- `POST /v2/direct/ack`: admitted Agent mTLS, JSON `{clientId,pairingId,generation}`. HTTP 200 `{status:"paired"}`. Idempotent; pairing completion and endpoint generation acknowledgement persist before response. Unknown/future generations reject.
- `GET /v2/direct/session?transport=2`: admitted Agent mTLS and `X-Mobile-Egress-Protocol: direct/1`. Upgrade one WebSocket for the paired phone. Reuses tunnelwire v1 control envelopes and negotiated v2 binary data; role is Agent. No old `/v1/session` direct admission. New same-pair session displaces old only after admission; revocation closes all work.
- `GET /v2/direct/config`: admitted Agent mTLS, HTTP 200 `{update: "<signed bundle or empty>"}`. Phone checks on connection and every 30 seconds while active; a pending latest endpoint update is exported for the current pairing. Persist verified update, ACK desired generation at new endpoint, then reconnect as needed. Manual QR/file import handles an unreachable old endpoint.
- `POST /v2/direct/renew`: admitted Agent mTLS, JSON `{clientId,pairingId,csrPem}`; same-key renewal only, same identity response shape as enroll and HTTP 201. Preserve pairing identity; persist old/new serial admission until ACK of the new certificate then retire old serial. Phone renews when validity has less than seven days remaining. Already-expired trust requires re-pair.

Control HTTP responses <=256 KiB; requests <=64 KiB; unauthenticated enrollment admission bounded with finite timeout and no unbounded queue. Errors are finite machine-safe classes/messages, never raw certificate, capability, endpoint query, or target data. Only active paired (or enrolled awaiting ACK for ACK/recovery) identities are admitted; certificate validity alone is insufficient. No public Owner/admin/proxy API.

Authenticated control admission returns HTTP 503 `{error:"storage_unavailable"}` when the Client cannot read its protected state or is blocked after failed revocation persistence, and HTTP 401 `{error:"unauthorized"}` for rejected pairing admission. Enrollment also reports storage failure as 503, preserving uncertain pending keys. Phones interpret recovery errors only through the pinned connection and strict bounded response shape. A transport timeout or generic TLS failure is not proof of revocation, and error responses never authorize deleting saved trust.

## Endpoint updates

Export wrapper JSON: `{version:2,type:"mobile-egress-direct-endpoint-update",payload,signature}`; payload and signature are unpadded base64url. Decoded payload UTF-8 JSON is `{clientId,pairingId,generation,endpoint}`. Signature is ASN.1 DER ECDSA P-256/SHA-256 over UTF-8 `MobileEgress-Direct-Endpoint-v2\n` followed by the exact decoded payload bytes. Verify with pinned CA public key before applying payload. No reserialization for signature verification. Strict shape, exact identity binding, positive monotonic uint64 generation (mobile bounded to Int64), skipped generations allowed; identical current generation is idempotent, conflicting/current or older updates rejected. Updates cannot replace trust/key/proxy credentials. Configure generates new SAN server certificate from the same authority. Desired generation is durable; pending remains until phone ACK.

An existing Client may retain a noncanonical endpoint spelling in its signed payload. Phones verify those original bytes before normalizing the endpoint for local storage and transport. Compare validated authorities at equal generation: padded numeric ports, explicit/default port 443, DNS case and equivalent IP spelling do not create a conflicting update. A different hostname or numeric port at the same generation still rejects. IPv6 socket and certificate-validation hostnames are unbracketed; HTTP authorities contain exactly one bracket pair.

## Client local integration contract

`nodeservice.NewDirect(repository, platform, architecture, version)` returns a manager with `Run(context.Context) error`, `Status() StandaloneStatus`, `Configure(context.Context, DirectConfiguration) error`, `IssueInvitation(context.Context) (string,error)`, `CancelInvitation(context.Context) error`, `ExportEndpointUpdate(context.Context) (string,error)`, `Revoke(context.Context) error`, `Proxy(context.Context,string) (string,error)`.

`DirectConfiguration` JSON: `bindAddress`, `endpoint`, `displayName`; default bind `:8443`. `StandaloneStatus` retains existing safe fields and adds `clientId`, `displayName`, `bindAddress`, `endpoint`, `paired`, `updatePending`, `invitationExpiresAt` (optional). Status never contains capability, cert/private key, or proxy password. Root owns Client UI/IPC/entrypoint; Go implementer owns nodeservice and transport; Android/iOS own their directories. Communicate interface changes before editing another owner's files.

## Runtime and compatibility

Ten records per phone including pending/disabled. One phone per Client; one outbound cellular WebSocket per Client. Isolate stream IDs by Client/session generation. Shared phone directional budgets 8192 frames/64 MiB including transport debt, 32 frames per stream; bounded aggregate control work and per-peer fairness. Preserve existing exact-byte/EOF/backpressure work. Explicit Start/Stop, per-peer enable/remove, global rotation. Android foreground service; iOS active foreground with default-on keep-awake scoped to active Start intent. No relay fallback or Wi-Fi transport.

Registry migration invalidates old active relay configuration, preserves recovery data securely, and requires fresh pairing. Internal legacy type names can temporarily remain where reused codecs require them, but production entrypoints must never dial a relay. Hardware/signing/release evidence is separate from unit or loopback success.

Renewal returns the currently acknowledged endpoint generation, never an unseen desired generation. If a renewal response is lost and the old certificate later acknowledges a signed endpoint update, retrying renewal returns the identical issued certificate and serial with the newer acknowledged generation. Only a signed endpoint update advances local endpoint generation. Configuring a new advertised origin invalidates unredeemed invitations; already-issued enrollment recovery bound to the CSR keeps the original response generation, and the phone polls configuration after ACK.
