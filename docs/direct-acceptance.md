## Behavioral coverage and review corrections

- Real Go loopback TLS/mTLS tests cover enrollment, ACK gating, accepted phone sessions, exact tail/EOF delivery, session replacement and persistent revocation. Public admission, strict decoding, DNS candidate policy and safe status have regression coverage.
- Both phone registries cover ten-record admission, disabled/pending entries, lost responses and acknowledgements, same-key recovery, skipped endpoint generations and isolation of identical stream IDs across Clients.
- Definitely-unsent expired invitations and exact pinned enrollment rejections release the matching pending slot transactionally. Unknown enrollment outcomes retain their key and CSR for recovery. A late response or rejection cannot overwrite/remove a replacement or issued record.
- Review corrections cover stale Android reconciliation after Stop/network replacement; iOS delayed renewal overwriting a disabled record; iOS rotation resume and Stop persistence under unavailable storage; native reservation refunds before read wakeup; and FIFO turns among actually ready peers. Queued and in-flight work share the global directional budgets. Aggregate overload remains a stream-local failure, not a rate limit or a fixed per-Client quota.
- Both phones stop a removed Client before storage writes. A separate private journal containing only Client IDs preserves distrust when credential deletion fails; the UI shows pending removal and other Clients continue. Tests cover relaunch, stale callbacks, failed journal writes, explicit retry/recovery and safe cleanup. iOS also prunes markers only for authoritatively absent records and commits that cleanup before fresh same-ID pairing. If every persistence write fails, the app reports that suppression is limited to the current process rather than claiming durable removal.
- Client review corrections cover stale pairing QR after endpoint changes, recoverable listener conflicts keeping local IPC available, serialized endpoint/firewall configuration, and listener status that does not claim phone reachability just because a socket is bound.
- Endpoint recovery retains the last acknowledged hostname in the server certificate across missed generations. Lost renewal responses retain the issued certificate but report the current acknowledged endpoint generation; unacknowledged desired endpoints are never implicitly accepted.
- Release tests cover direct-only 2.x assets, unchanged historical 1.x contracts, no cross-major phone fallback, exact source/signer/payload checks, and Mac verification before promotion. Independent release review also corrected the Windows-only download scope note.

These tests exercise software and local transport boundaries. They do not prove externally reachable deployment, handset cellular routing, signed secure-store access or sustained throughput.

The subsequent whole-plan review found six missed areas, now corrected with regressions under the [follow-up checklist](superpowers/plans/2026-10-03-direct-client-phone.md):

- Android credentials use an encrypted atomic file with durability barriers. Tests reproduce memory-visible/disk-failed commits, failure before/after replacement, restart, no premature ACK, and retention of keys after uncertain reservations. Legacy recovery is saved before retiring active preferences. A shared committed generation invalidates all readers after attempted writes while avoiding file reads, syncs and decryption on unchanged traffic-status refreshes.
- Equivalent IPv6 spelling, numeric ports, DNS case and default HTTPS ports work through invitation, update and ACK. Different authorities reject; existing signed payload spelling stays unchanged at its generation. Storage failures, including failed-revocation blocking, return 503 instead of a misleading authentication/enrollment rejection.
- iOS reconstructs rotation pause before sharing after relaunch, and the app action selects the required 30-second retry after an unchanged address. A suspended registry load cannot restore active state or keep-awake after inactivity; tests use the shared production app adapter.
- Android keeps Stop available during management work and after last-Client removal. Both phones show finite per-Client recovery actions, distinguish unavailable storage from unusable pairing, and preserve trust. Terminal peers wait for explicit retry without stalling other Clients. Late Android callbacks cannot erase a paused recovery state.

Focused regressions were observed failing before fixes. Independent review of the final durability/cache and iOS lifecycle/recovery changes found no additional defect; root reviewed the Go authority/authentication boundary and final Android callback ownership. Fresh Windows integration, native Mac targeted tests/vet/race, mobile gates, manifest/schema and whitespace checks passed. The preserved historical unified patch retains literal context whitespace by an exact-path Git attribute; its context was not reformatted.

The next review found five further integration gaps, now corrected and independently reviewed:

- iOS uses bare IPv6 addresses for socket/TLS validation and exactly one bracket pair in HTTP authorities; tests exercise the actual encoder and trust-policy configuration.
- Both phones verify the original signed endpoint bytes before canonicalization. Real retained-state Go exports cover skipped and equal-generation recovery through phone persistence and ACK, retaining pending status on failed writes. iOS native Keychain lookup/staging adapts only a transient identity; invalid role, serial or trust still rejects. Disposable native adapter tests do not prove entitled installed-device Keychain access.
- Android's actual row Retry action hands recovery to a registered service that confirms ownership. Transient maintenance failure continues through its retry loop. A stopped service performs one manual attempt and does not promise automatic recovery; disabled/removing records, terminal trust failures and cancellation remain protected.
- iOS retains delivered cellular loss/return in its inactive rotation checkpoint, preserving elapsed hold time without starting probes, timers or traffic. Full-cycle/relaunch, early return, missing observations, cancellation and queued-Start regressions pass. The guided flow explicitly returns to the app with Airplane Mode on; missing observations are not invented.
- The actual iOS dashboard and copied status use the tested foreground status adapter, showing Unknown until a cellular observation arrives and keeping availability separate from sharing intent and Client connections. Parity evidence now points to that production path.

Final second-review validation: Windows integration passed; Android 289 tests/lint/debug build passed; the final 131-file iOS snapshot passed 361 warning-strict Swift tests and 361 Xcode package tests (two hardware skips in each), plus unsigned iPhoneOS/Simulator app and cleanup-extension builds. Manifest/schema and whitespace checks passed. Scoped independent review found no additional defect. Changes remain uncommitted; no signing, installation or publication occurred during these corrections.
