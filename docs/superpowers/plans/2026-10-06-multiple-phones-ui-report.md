## Steps and choices

1. Read project AGENTS requirements, approved multiple-phone plan, PowerShell command-safety skill, TDD skill and writing-good-tests reference. Parent supplied clean baseline evidence at `9634be9`: existing 71 frontend tests and clientapp Go tests passed. Read existing App, IPC, firewall wrapper, QR renderer, HTML and real frontend handlers before changing them.
2. Added Go boundary regressions for additive phone status, unchanged legacy response shape, secret-free status, malformed payloads, explicit stable phone selection, clipboard-only proxy secrets, unknown IDs, and unsupported service failures. Initial red run reported absent frozen nodeservice types and new response/App APIs. Nodeservice agent subsequently supplied frozen exported types/methods; those files were not edited here.
3. Added optional `PhoneService` without changing the original `Service` / `DirectService` contracts. Forwarded it through the existing firewall wrapper and authenticated local IPC client. Request fields `phoneId`, `name`, `kind` and response fields `phones`, `invitation` are additive and omitted in old status responses. New commands reject extra settings, invalid IDs, invalid names and unknown proxy formats before service dispatch. Failed commands clear response values/invitations. New API failures propagate; no legacy mutation/copy/export fallback occurs.
4. Added frozen App bindings: `Phones`, `AddPhone`, `CancelPhoneInvitation`, `RenamePhone`, `RevokePhone`, `CopyPhoneProxy`, `ExportPhoneEndpointUpdate`, `CopyPhoneEndpointUpdate`, `RetryPhoneProxy`. `AddPhone` returns flattened `phoneId`, `bundle`, `qrDataUrl`. Proxy secrets reach the native clipboard only on explicit copy; status never adds secret-bearing fields. Existing QR compression, exact module rendering, quiet zone and native themes remain unchanged.
5. Resolved one binding omission with the parent: the add flow also needs `CopyPhoneInvitation(phoneID)`. Parent approved this additive binding and updated the shared plan. Invitation cache keys are stable IDs from the explicit Add result. Scoped copy checks the current sole pending ID, rejects wrong/externally canceled IDs, and cannot implicitly copy through legacy `CopyInvitation`. Successful cancel/removal clears only the affected cache; shared configuration changes clear stale invitations even when firewall application fails after saving. Removing a sibling preserves the active invitation.
6. Added failing frontend tests using the actual app.js handlers with the existing bridge/DOM harness. New tests failed for the missing phone-list/add/settings behavior while all 71 pre-existing tests remained green. Expanded the DOM utility to model native-created nodes and focus so behavior is tested without HTML-source assertions.
7. Implemented accessible phone rows using text nodes for names, list/listitem roles, unique per-phone accessible button labels, public loopback addresses, and explicit ID closures. Rows expose each phone's HTTP/SOCKS clipboard copy and settings. Add capacity respects ten slots and resumes the sole pending invitation. Settings expose rename, signed update QR/copy, stable-port retry and confirmed removal. Failed removal keeps its confirmation and uncertainty message available for retry.
8. Retained the first-phone account/direct setup. Additional-phone add starts at pairing with an optional name and skips computer activation/configuration. Cancellation returns to the dashboard and leaves siblings intact. Verification derives connected/update/port state from the selected ID; an already connected sibling never completes the new phone's setup. Phone selection changes clear displayed private QR/text and reject late async invitation/update results.
9. A new focus regression failed because rebuilding rows on every poll detached the focused action. Reused stable-ID row nodes and only replace the list when IDs/order change. The regression and suite then passed. Rename edits are not overwritten by polling.
10. First integrated clientapp Go run timed out in `TestPhoneIPCRejectsInvalidPayloadsWithoutReturningSecrets`. Stack evidence showed both sides writing on unbuffered `net.Pipe`: the pre-existing helper synchronously wrote a longer request plus trailing newline before reading the response. Updated only the test helper to read/write concurrently and release a trailing write after the response. Full clientapp tests passed afterward in 25.123 seconds.
11. A raw-control label regression exposed trimming before validation in the new IPC/App helper: leading newline and trailing tab could normalize to a valid name before reaching authority. Moved control validation before trimming and retained 64-rune counting. The 64-emoji boundary passes; 65 runes, raw controls and blank rename reject without changing the saved name. Phone inputs allow 128 UTF-16 code units so 64 non-BMP runes remain enterable; authoritative 64-rune validation still applies.
12. Independent review found two P2 state issues. Added regressions that failed first: `shared fatal service failure stays visible for a selected healthy phone` and `dashboard return cannot resurrect healthy phone state after a failed poll`. Preserve shared error/unavailable state when merging a selected phone, synchronize the shared snapshot on failed refresh, and suppress row success under shared failure. Nodeservice owner confirmed global error means shared failure, while per-phone blocked ports use `proxy_error`. Healthy siblings retain their separate state under a per-phone error. Corrected removal copy: new pairing receives its own private proxy details.
13. Added real-authority IPC integration coverage: reserve one phone using `NewDirect` + in-memory protected repository, reject unknown IDs for proxy/rename/revoke/cancel/export/retry, preserve the saved name/record, and verify no invitation/capability/password in status. These checks use the real service implementation; bridge doubles cover platform-independent App/UI behavior.
